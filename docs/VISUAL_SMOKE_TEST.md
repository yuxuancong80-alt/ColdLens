# Visual-only 本地冒烟测试

> 日期：2026-08-13  
> 范围：固定 32 张封面，不训练模型，不读取最终测试标签

## 1. 本轮目的

验证以下工程环节，而不是追求推荐指标：

1. 能否不解压 ZIP，直接按视频 ID 读取封面；
2. 能否统一缩放图片并生成固定维度向量；
3. 向量能否进行归一化和余弦相似度计算；
4. 本地是否具备继续视觉实验的最低能力。

## 2. 初始环境阻塞与处理

初步选择 MobileNetV3-Small 作为预训练视觉最低基线：官方权重约 9.8MB、约 250 万参数、0.06 GFLOPS，适合 CPU。PyTorch 官方支持 Windows 上的 Python 3.9–3.12。

2026-08-13 首次使用 pip 解析依赖时，外部包索引连续超时，因此先用 Windows 自带 `System.Drawing` 完成零依赖链路冒烟测试。2026-08-14 改为从 PyTorch 官方 CPU wheel 索引核对版本和文件大小，使用可断点续传方式将核心 wheel 下载到 D 盘，再安装其余依赖。

最终本地隔离环境为 Python 3.12.10、`torch 2.10.0+cpu`、`torchvision 0.25.0+cpu`、NumPy 2.5.2 和 Pillow 12.3.0。虚拟环境约 636MiB，两个核心离线 wheel 合计约 112.5MiB；所有缓存、临时文件和权重均位于 `D:\ColdLens`。

参考：

- [PyTorch 本地安装说明](https://docs.pytorch.org/get-started/locally/)
- [Torchvision MobileNetV3-Small](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.mobilenet_v3_small.html)

## 3. 冒烟特征

- 将每张图片缩放为 8×8。
- 每个像素保留 RGB 三通道，共 192 维。
- 对每张图片做均值中心化和 L2 归一化。
- 该特征只表示粗粒度颜色和空间布局，不是预训练语义嵌入。

## 4. 结果

| 图片对 | 余弦相似度 | 判断 |
|---|---:|---|
| 相同《火影忍者》画面 | 0.99994 | 符合预期 |
| 同漫画模板、不同集数 | 0.999997 | 符合预期 |
| 狗 vs 足球封面 | 0.81649 | 偏高，受中央竖幅与黑边影响 |
| 游戏 vs 电影封面 | 0.90880 | 明显误判 |

所有 32 个向量均为 192 维单位向量，固定样本输出文件 SHA-256 为 `11b594a593df7e6b3379070c056b0bc68bbae35131bef8f3797ee648bde4e883`。

## 5. 结论

- ZIP 直读、图片解码、统一缩放、向量输出和余弦比较链路全部可行。
- 8×8 RGB 特征不能作为正式 Visual-only 基线；它对版式和颜色过度敏感，缺少对象与语义理解。
- 不进行全量 RGB 特征提取，避免制造一个明知薄弱的“版本进展”。
- 下一步仍应使用轻量预训练视觉编码器，例如 MobileNetV3-Small 的分类头前特征。
- 先在本地测量预训练编码器处理 32–128 张图片的速度；仅当预计全量 CPU 时间明显不合理，且公司政策允许时，才使用公司服务器。

## 6. 公司服务器边界

当前没有使用公司服务器的必要。模型依赖、权重、输入输出格式和少量样本必须先在本地验证。若后续使用服务器，只上传代码、模型权重和必要输入；完成后将特征和日志回传本地并核验，再清理明确的个人临时目录。

## 7. 预训练 MobileNetV3-Small 冒烟结果

2026-08-14 使用官方 `MobileNet_V3_Small_Weights.IMAGENET1K_V1`。特征取分类器之前的全局平均池化输出，共 576 维，并逐行做 L2 归一化。固定 32 张样本结果如下：

| 图片对 | 余弦相似度 | 判断 |
|---|---:|---|
| 相同《火影忍者》画面 | 0.99908 | 符合预期 |
| 同漫画模板、不同集数 | 0.99722 | 符合预期 |
| dHash 误报：狗 vs 足球封面 | 0.55522 | 明显低于同画面 |
| dHash 误报：游戏 vs 电影封面 | 0.49688 | 明显低于同画面 |

- 32×576 输出形状、单位范数和重复推理确定性检查全部通过，重复最大绝对差为 0。
- 样本中三个余弦相似度近 1 的 top pair 实为 JPEG 字节完全相同；另一高相似组的 dHash 也完全相同，没有证据表明是模型塌缩。
- 512 张流式基准耗时 5.46 秒，约 93.9 张/秒；由此估计本地全量约 205 秒。

## 8. 全量特征提取

随后在本地 CPU 完成全部 19,220 张封面的流式提取，未使用公司服务器：

- 实际耗时：235.49 秒，约 81.6 张/秒；
- 输出形状：`19220 × 576`，float32；
- item ID 与封面审计表完整一一对应、严格递增且无重复；
- 向量文件大小：44,283,008 字节；
- 向量文件 SHA-256：`58430b56a5c4f62a5a451d0b52b221ae74e0810ad0f6de71bae2f958b9ddc3ac`；
- item ID 文件 SHA-256：`c96d643ce34f69a8f2283811dff9b1af6d7d6bbe5dbe9e766ed228dbd8b42944`；
- 全量前 512 行与独立 512 张基准逐值一致，最大绝对差为 0。

因此视觉特征提取继续采用本地 CPU；A100 对当前冻结编码器没有必要。该结果只证明工程可行和特征行为基本合理，尚不能证明 Visual-only 推荐质量，下一步必须只在 Validation Cold 上建立公平基线。
