# ColdLens 数据与产品分析协议 v1

> 冻结日期：2026-08-14  
> 用途：补充产品判断，不选择新模型、不修改已冻结 Test 结论

## 1. 分析问题

1. 用户互动和视频互动是否呈长尾分布？
2. 头部 1%、5%、10%、20% 的用户/视频贡献了多少互动？
3. `split_v1` 的 Validation Cold 提供了多大规模的模型侧冷启动机会？
4. 用户训练历史长度与 Text-only、Visual-only 的 Validation Recall@10 有什么关系？
5. 两种模型的 Top-10 候选覆盖与曝光集中度有何差异？
6. 这些结果对 MVP 覆盖人群、护栏和后续数据建设意味着什么？

## 2. 数据范围

### 全量描述性统计

只读取 `MicroLens-50k_pairs.csv` 与标题文件，用于数据集生态描述。全量统计不得作为时序模型特征，也不得被解释为预测时可用信息。

### 模型诊断

只读取：

- `dev_train.csv.gz`
- `validation_cold.csv.gz`
- `validation_cold_candidates.csv.gz`
- 已冻结标题与视觉特征

脚本不得读取 `final_train`、`test_cold`、最终 Test 报告或任何 Test 标签。诊断只描述已经冻结的 Text-only 和 Visual-only Validation 行为，不用于继续调权重。

## 3. 冻结指标

### 长尾与集中度

- 用户/视频互动数的 min、P25、P50、P75、P90、P95、P99、max
- 头部 1%、5%、10%、20% 实体的互动占比
- 包含零曝光候选的 Gini 系数

头部实体数量使用 `ceil(比例 × 实体数)`。所有互动均按原始行计数；数据审计已确认没有重复 user-item 行。

### Validation 产品诊断

- 历史长度分组固定为 `1–3`、`4–6`、`7–10`、`11+`
- 每组报告用户数及 Text/Visual Recall@10
- Top-10 Catalog Coverage：至少进入一名用户 Top-10 的候选数 / 完整冷候选数
- Top-1% / Top-10% Exposure Share：按候选获得的推荐槽位数降序，计算头部候选占全部 Top-10 槽位的比例
- Exposure Gini：对完整冷候选池（包括零曝光候选）计算曝光次数 Gini
- Text–Visual Top-10 平均交集，仅作互补性描述

覆盖率不是推荐质量，低集中度也不必然更好。确定性随机打破同分只用于复现；若大量零分，它可能人为增加覆盖，因此同时报告零分用户数。

## 4. 明确排除

- 不分析内容类别：数据没有可靠类别字段。
- 不把全局点赞/播放汇总作为模型特征、时间安全热度或真实曝光分母。
- 不生成新的 Test 指标，不重新比较被拒绝的融合模型。
- 不把历史长度分组差异解释为因果效应；它可能混合用户活跃度、兴趣稳定性与正例数量。
- 不把评论正反馈指标外推为 CTR、播放时长或留存。

## 5. 接受与停止规则

本轮没有模型接受门槛。输出必须完整报告上述冻结指标，即使结论不利于当前方案。结果只用于：

- 定义 MVP 首批覆盖人群；
- 识别曝光集中与弱历史用户风险；
- 形成下一轮数据建设或线上实验假设。

完成报告后停止使用同一 Validation 追加无预注册的模型调优。
