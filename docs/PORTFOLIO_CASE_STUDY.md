# ColdLens：AI 产品经理作品集案例

## 1. 案例摘要

**问题**：短视频在缺少历史互动时，推荐系统无法依赖成熟的 ID 行为特征。标题和封面能否提供足够的冷启动匹配信号？新增视觉链路是否值得它带来的研发、推理与监控成本？

**我的角色**：以 AI 产品经理视角完成问题定义、数据适用性审计、指标与接受门槛设计、实验优先级、成本控制、失败方案淘汰及上线验证方案设计；同时实现本地可复现实验，确保决策可以被检查。

**最终判断**：标题 TF-IDF 是当前最可靠的轻量方案。封面视觉包含信号，但三种融合方法都没有同时改善冻结的 Recall@10 与 NDCG@10，不应为了“多模态”标签进入主链路。

## 2. 先纠正问题定义

最初假设是“新发布短视频冷启动”。数据审计后发现，MicroLens-50K 的时间戳来自公开评论记录，第一次出现评论并不等于上传时间。因此项目收窄为：

> 对训练窗口中零交互、评测窗口首次被观察到的候选视频，使用标题和封面匹配具有历史兴趣的用户。

这是严格的**模型侧 Item Cold-Start**，但不是平台真实发布时刻冷启动。这个修正避免了用数据无法支持的说法包装项目。

同时，评论是较高意图正反馈，却缺少曝光和未点击样本。项目能验证排序代理任务，不能声称提升 CTR、播放时长或留存。

## 3. 我如何拆解决策

| 决策 | 选择 | 原因与代价 |
|---|---|---|
| 主数据集 | MicroLens-50K | 用户、视频、评论时间戳与标题可对齐；规模适合本地迭代。代价是反馈类型和上传时间受限。 |
| 冷启动定义 | 训练窗口零交互的 Item Cold | 可以由已知数据严格验证；不冒充真实上线时间。 |
| 数据切分 | 80%/90% 全局时间点形成 Validation/Test | 模拟时间向前，隔离调参与最终评估；不同窗口分布不可直接等同。 |
| 排序口径 | 完整冷候选池 | 避免采样负例让指标虚高；计算量略增但可控。 |
| MVP 信号 | 标题优先，封面其次 | 先验证低成本信号，再决定是否承担视觉依赖。 |
| 融合门槛 | Recall@10、NDCG@10 同时严格提升 | 兼顾找回正例和头部排序；会拒绝只改善单一指标的方案。 |
| Test 使用 | 冻结模型后一次性运行 | 降低反复看 Test 导致的选择偏差；失去在 Test 上继续修饰结果的自由。 |

## 4. 实验路线与去留

### 4.1 Text-only：进入最终候选

用训练视频标题拟合 TF-IDF，将用户历史评论视频的标题向量汇总为兴趣画像，再对所有冷候选做余弦排序。

- Validation Recall@10：0.12797
- Validation NDCG@10：0.08211
- 近重复标题排除后，主要结论仍成立
- 低历史用户明显更难，但该关系同时受活跃度和兴趣稳定性影响，不能解释为因果

这个模型简单、可解释、资源要求低，适合作为 MVP 兜底。

### 4.2 Visual-only：保留为独立证据，不替代 Text

用 ImageNet 预训练 MobileNetV3-Small 提取 576 维封面向量，用户画像为历史封面向量的归一化汇总。

- Validation Recall@10：0.04253
- Validation NDCG@10：0.02365
- 19,220 张封面在本地 CPU 完成特征提取，耗时 235.49 秒
- dHash 清洁敏感性分析未改变结论

视觉明显不是纯随机，但头部排序远弱于标题，因此不应单独承担主方案。

### 4.3 三类融合：全部拒绝

1. **全局排名融合**：检查五档 Text 权重，最优点退化为纯 Text；任何正视觉权重都降低 Recall/NDCG/HitRate@10。
2. **低文本置信度门控**：低最高文本相似度没有成功识别“视觉更可靠”的用户；最佳切换比例为 0%。
3. **学习式晚融合**：内部代理任务准确率提高，外层 Validation NDCG@10 小幅提高，但 Recall@10 下降，未通过双指标门槛。

这里最重要的不是“做了三个模型”，而是及时停止继续在同一个 Validation 上追加启发式规则。反复尝试会扩大多重比较与过拟合风险，也会让产品路线被沉没成本绑架。

## 5. 冻结 Test 与最终结果

最终只测试已冻结的 Text-only 主候选与 Visual-only 独立基线；三个被 Validation 拒绝的融合模型没有查看 Test 指标。

| 模型 | Recall@10 | NDCG@10 | HitRate@10 | Recall@50 |
|---|---:|---:|---:|---:|
| **Text-only** | **0.12551** | **0.07969** | **0.15214** | **0.23490** |
| Visual-only | 0.04543 | 0.02800 | 0.05800 | 0.13652 |

Test 包含 1,008 个完整冷候选、13,810 名用户和 18,812 个正例。Text 的相对优势与 Validation 一致，没有发生数量级失效。排除 13 个跨训练边界 `dHash=0` 候选后，Text Recall@10/NDCG@10 为 0.12601/0.07997，结论不变。

## 6. 从实验到产品方案

### 当前 MVP

在真实系统已有行为模型不可用或不可靠时，使用标题兴趣匹配提供候选排序/兜底分。它应是现有推荐链路的冷启动分支，不是替换完整推荐系统。

### 为什么暂不上视觉融合

- 离线收益没有通过事前门槛；
- 需要新增图片获取、解码、模型版本、特征存储、缺失值和延迟监控；
- “存在互补用户”只是 oracle 空间，不等于已有门控能识别这些用户；
- 过早上线会让系统复杂度先确定，而用户价值仍未确定。

### 线上验证草案（尚未执行）

**实验对象**：满足“无可靠行为特征”条件的新内容流量；先明确该条件在生产中的可计算定义。

**对照与实验**：对照组使用现有冷启动策略，实验组在相同召回预算下加入/替换为 Text-only 内容匹配。随机化单位需结合跨设备与社交传播污染风险决定；默认优先用户级，若请求级更合适则需评估串组。

**主指标**：新内容的有效消费率或高意图互动率。必须先由业务定义“有效消费”，不能直接沿用公开评论代理标签。

**护栏**：快速划走、不感兴趣/投诉、整体消费时长、成熟内容挤占、创作者覆盖、P95/P99 延迟与特征缺失率。

**分析前置**：埋点 A/A、样本比例失衡（SRM）、最小可检测效应和样本量、实验周期覆盖工作日/周末、重复检验控制。由于缺少真实基线率、流量与目标 MDE，本项目不伪造样本量数字。

## 7. 风险清单

| 风险 | 已做控制 | 仍未解决 |
|---|---|---|
| 时间泄漏 | 时间切分；训练词表/画像只读对应历史 | 首次评论不等于上传时间 |
| 负例偏差 | 全冷候选排序，不做 sampled negatives | 未曝光不能被视为真实负反馈 |
| 视觉近重复 | dHash 跨边界敏感性分析 | dHash 只能筛查，不能完整定义语义重复 |
| 指标选择偏差 | 预先冻结接受门槛与 Test 范围 | 多轮 Validation 实验仍可能产生开发集适配 |
| 代理目标错位 | 比较内部代理任务与外层排序结果 | 缺少真实线上价值标签 |
| 工程成本 | 本地 CPU 验证，先轻后重 | 生产延迟、稳定性与特征成本尚未实测 |

## 8. 我会如何继续

不是继续在同一 Validation 上搜索权重。下一轮应建立新的证据：

1. 获取真实上传时间、曝光与消费标签，重新定义生产冷启动窗口；
2. 针对“Text 失败但 Visual 成功”的样本形成可验证分群假设；
3. 在新的开发窗口测试跨模态语义或质量特征，并单独冻结新门槛；
4. 只有离线收益覆盖链路成本后，才进入线上小流量实验。

## 9. 面试时我会强调什么

- 我没有把数据能支持的“模型侧冷启动”夸大成真实发布冷启动。
- 我把 Test 当成最终审计，而不是继续调参的反馈面板。
- 我接受“复杂方案不如简单基线”，并把失败转化成代理目标错位、用户识别失败和工程 ROI 的产品判断。
- 我能解释每个数字代表什么，也能明确它不代表什么。
