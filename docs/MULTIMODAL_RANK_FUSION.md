# Text–Visual 排名融合验证

> 日期：2026-08-14  
> 协议：`split_v1`  
> 范围：Validation Cold；未运行模型测试指标

## 1. 预先冻结的选择规则

在查看融合网格结果前固定以下规则：

- 不直接相加 TF-IDF 与 MobileNet 余弦分数，因为两种分数的分布和稀疏性不同。
- 先将每名用户的 Text、Visual 候选分别转换为从 0 开始的排名。
- 融合成本为 `text_weight × text_rank + (1 - text_weight) × visual_rank`，成本越低排名越高。
- 文本权重只检查 `0、0.25、0.5、0.75、1` 五档。
- 主选择指标为 Validation `NDCG@10`，并列时使用 `Recall@10`。
- 主集合选出的权重原样用于 `visual_clean_dhash0`，不在清洁集合重新调参。

联合脚本首先强制复现已有 Text、Visual 和清洁 Visual 端点；任一指标误差超过 `1e-12` 就中止。最终三个端点检查均通过。

## 2. 用户级互补性

Text 与 Visual 的 Top-10 推荐集合平均只交集 0.332 个候选，平均 Jaccard 为 0.0181，说明两种排序差异很大。

| Top-10 正例命中状态 | 用户数 |
|---|---:|
| Text 与 Visual 都命中 | 417 |
| 仅 Text 命中 | 1,733 |
| 仅 Visual 命中 | 346 |
| 两者都未命中 | 11,254 |

Text 共命中 2,150 名用户，HitRate@10 为 0.15636。若存在知道每名用户该选哪种模态的 oracle，Text 或 Visual 任一命中可覆盖 2,496 名用户，约 0.18153；相比 Text 多 346 名用户。该 oracle 只是互补性上界，不是可部署模型。

## 3. 五档融合结果

| Text 权重 | Visual 权重 | Recall@10 | NDCG@10 | HitRate@10 |
|---:|---:|---:|---:|---:|
| 0.00 | 1.00 | 0.04253 | 0.02365 | 0.05549 |
| 0.25 | 0.75 | 0.07275 | 0.04654 | 0.09375 |
| 0.50 | 0.50 | 0.08452 | 0.05363 | 0.10735 |
| 0.75 | 0.25 | 0.09735 | 0.06098 | 0.12225 |
| 1.00 | 0.00 | **0.12797** | **0.08211** | **0.15636** |

最佳验证权重为 Text 1.0、Visual 0.0，即退化为原 Text-only。全局排名加权没有获得多模态提升，不能把权重 0.75 等较差结果包装为融合成果。

## 4. `visual_clean_dhash0`

主验证选择的权重 1.0 原样应用到清洁集合，因此融合结果等于清洁 Text 端点：

- Recall@10：0.12822；
- NDCG@10：0.08240；
- HitRate@10：0.15630。

清洁 Visual 端点也精确复现 Recall@10 = 0.04261、NDCG@10 = 0.02362。清洁集合没有改变“全局融合不优于文本”的判断。

## 5. 独立判断

- 视觉具有用户级增量命中，但当前全局权重无法识别视觉何时可信。
- 排名差异很大不自动等于互补收益；弱模态加入多数用户排序后可能稀释强文本信号。
- 五档网格较粗，可能错过靠近 Text 1.0 的小权重，但在看到结果后临时细搜会增加验证集选择偏差，不能把这种追加搜索当作预注册结论。
- 若继续探索，应先分析“仅 Visual 命中”用户是否能被不使用验证标签的可观测置信度识别，例如文本画像为空、最高文本相似度低或 Top-1/Top-2 间隔小；再预先冻结一条条件式门控规则。
- 如果没有稳定门控信号，应保留 Text-only 为最终候选，并把视觉分支作为诚实的负结果与后续改进方向。
