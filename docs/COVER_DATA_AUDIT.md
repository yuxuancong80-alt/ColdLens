### 感知哈希筛查

使用 9×8 缩放后的 64 位 dHash，只做疑似近重复筛查：

| 边界 | 冷候选 | dHash 距离 0 | 距离 ≤2 | 距离 ≤5 |
|---|---:|---:|---:|---:|
| 开发训练 → 验证冷候选 | 1,305 | 21 | 77 | 116 |
| 最终训练 → 测试冷候选 | 1,008 | 13 | 50 | 76 |

人工抽查发现：

- 部分距离 0 是实质相同画面，例如不同视频 ID 使用同一《火影忍者》封面。
- 部分是同系列或共享局部模板。
- 部分是明显误报，例如不同主题图片都采用黑边和中央竖幅构图。

dHash 不能作为“自动删除全部近邻”的充分证据。

## 5. 冻结处理规则

1. 保留原始 `split_v1` 作为主协议，不因查看视觉数据后修改原始时间边界。
2. Visual-only 和 Multimodal 除主结果外，必须增加 `visual_clean_dhash0` 敏感性结果。
3. `visual_clean_dhash0` 对每个验证/测试冷候选，若其 dHash 与对应训练窗任一图片完全相同，则从候选池和正例中排除。
4. Text-only 也必须在同一清洁候选池重跑，保证跨模型比较使用相同样本。
5. dHash 距离 1–5 只用于分层报告和人工抽查，不自动删除。
6. 提取视觉嵌入后，再用高余弦相似度检查更可靠的近重复风险；阈值必须在验证集确定，不能查看测试指标后调整。

该规则是保守敏感性分析，不声称 dHash=0 的全部样本都是真重复。

## 6. Test 使用边界

本次为数据质量与跨集合泄漏审计，读取了测试候选的封面指纹，并人工抽查少量无标签图片；没有训练模型、查看用户正例排名或计算测试推荐指标。后续不得根据测试封面案例调整模型结构或阈值。
