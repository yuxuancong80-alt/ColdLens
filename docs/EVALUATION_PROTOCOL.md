# ColdLens 离线评测协议（split_v1）

> 冻结日期：2026-08-13  
> 主任务：基于评论正反馈的严格模型侧新视频冷启动排序

## 1. 为什么采用两阶段时间切分

模型选择和最终测试必须隔离：

1. **开发阶段**：使用时间早于 `1661524096284` 毫秒的交互训练，在随后时间窗验证。
2. **最终阶段**：冻结模型结构和超参数后，使用时间早于 `1662252337828` 毫秒的交互重新训练，在最后时间窗测试。

这样既避免反复查看测试集调参，又允许最终模型利用验证期之前已经发生的历史行为。

## 2. 数据集合

### 开发训练集

- 条件：`timestamp < 1661524096284`。
- 287,766 条交互、49,416 名用户、16,907 个视频。

### 冷启动验证集

- 时间：`1661524096284 <= timestamp < 1662252337828`。
- 冷视频定义：开发训练集中零交互。
- 用户条件：开发训练集中至少有一条历史交互。
- 候选池：验证窗口中首次观测到的全部 1,305 个冷视频。
- 评测正例：18,508 个用户—视频对，覆盖 13,750 名用户。

### 最终训练集

- 条件：`timestamp < 1662252337828`。
- 323,736 条交互、49,887 名用户、18,212 个视频。
- 模型结构、超参数和停止规则必须在使用该集合前冻结。

### 冷启动测试集

- 时间：`timestamp >= 1662252337828`。
- 冷视频定义：最终训练集中零交互。
- 用户条件：最终训练集中至少有一条历史交互。
- 候选池：测试窗口中首次观测到的全部 1,008 个冷视频。
- 评测正例：18,812 个用户—视频对，覆盖 13,810 名用户。

## 3. 排序与指标

- 每名用户对完整冷候选池排序，不采样负例。
- 同一用户在窗口内可能有多个正例，先聚合为正例集合。
- 报告 `Recall@5/10/20/50`、`NDCG@5/10/20/50` 和 `HitRate@5/10/20/50`。
- 用户级计算指标，再对用户取宏平均，避免高活跃用户完全主导结果。
- 所有方法必须使用同一候选池、同一用户集合和同一正例定义。

完整候选池消除了“不同负样本让不同模型受益”的问题，但仍有隐式反馈偏差：没有评论不代表用户不喜欢，也不代表用户真正获得过曝光。

## 4. Warm 参照集

同时保留验证和测试时间窗中的 Warm 交互：视频在对应训练窗内至少出现一次，用户也有训练历史。

Warm 评测用于回答：

- Popular 和纯 ID 模型是否正常工作；
- 内容模型的收益是否只来自冷启动条件；
- 冷启动改进是否以常规推荐性能明显下降为代价。

Warm 排序时必须从候选列表中排除用户训练历史中已经互动的视频，当前正例除外。Warm 候选池和 Cold 候选池不得混用后再只汇报总体平均。

## 5. 基线口径

### Cold 主集合

1. Random：评测管线的烟雾测试。
2. ID/UNK：展示纯 ID 方法面对未见视频时的退化，不把并列随机结果包装为有效个性化。
3. Text-only：标题内容表示。
4. Visual-only：封面内容表示。
5. Multimodal：标题与封面的简单、可解释融合。

训练期 Popular 对所有严格冷视频的训练热门度均为零，因此无法产生有意义的冷视频排序。全局点赞/播放统计含未来信息，不得替代训练热门度。

### Warm 参照集合

1. Popular。
2. 轻量 ID-based 模型。
3. Text-only、Visual-only、Multimodal。

## 6. 防泄漏规则

- 测试冷视频不得出现在最终训练交互中。
- 验证冷视频不得出现在开发训练交互中。
- 全局点赞、播放量以及任何使用完整时间范围计算的聚合统计不得进入模型。
- 标准化、降维、阈值选择和融合权重只能用对应训练集及验证集确定。
- 测试指标只在所有选择冻结后运行；调试代码只能使用开发训练和验证集合。
- 标题和封面被视为视频进入候选池时即可获得的内容信息，此项是业务假设而非数据日志证明。

## 7. Random 烟雾测试

固定随机种子 `20260813`，对每名用户用 `seed + user_id` 独立打乱候选池。该结果只验证指标量级和管线连通性，不作为模型成果：

| 集合 | 候选数 | 用户数 | Recall@10 | NDCG@10 | HitRate@10 |
|---|---:|---:|---:|---:|---:|
| Validation Cold | 1,305 | 13,750 | 0.00709 | 0.00363 | 0.00931 |
| Test Cold | 1,008 | 13,810 | 0.00980 | 0.00474 | 0.01318 |

## 9. 视觉近重复敏感性协议

封面审计发现少量跨训练—冷候选的 dHash 相同图片，其中既有真实相同画面，也有低分辨率哈希误报。保留 `split_v1` 主结果，并额外报告 `visual_clean_dhash0`：排除与对应训练窗任一封面 dHash 完全相同的冷候选。Text、Visual 和 Multimodal 必须在同一清洁集合重跑。距离 1–5 不自动删除，详细依据见 `docs/COVER_DATA_AUDIT.md`。
