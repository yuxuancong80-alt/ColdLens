# ColdLens 3–5 分钟面试讲解路线

> 目标：不用背算法细节，也能把问题、实验、决策和边界讲清楚。先理解再复述，不建议逐字背诵。

## 一、开始前只记住四件事

1. 项目解决的是**新视频没有历史交互时的排序问题**，不是完整短视频平台。
2. 数据中的用户行为是**公开评论**，不是点击、观看或曝光。
3. Text 看标题，Visual 看封面；当前实验中 Text 明显更好。
4. 三类融合没有通过 Validation 门槛，所以没有进入最终 Test。

## 二、3–5 分钟完整讲解稿

### 0:00–0:35｜问题是什么

“我做的是一个短视频 Item Cold-Start 推荐项目。核心问题是：一个新视频还没有用户交互时，传统依赖视频 ID 和历史行为的推荐方法很难判断应该把它推荐给谁。

我的方案是先利用视频自身内容做冷启动。Text 方案读取标题，Visual 方案读取封面，再结合用户过去评论过的视频，判断用户可能对哪些新视频感兴趣。”

此时打开 Demo 的“实验样例”，指向“最近历史”和“完整冷候选池中的 Top-10”。

### 0:35–1:15｜为什么先改了问题定义

“项目最初想研究真实的新发布视频，但数据审计后发现，这个数据集记录的是公开评论时间，而不是视频上传时间。第一次观察到评论，不等于视频刚发布。

所以我把项目收窄为模型侧 Item Cold-Start：测试候选视频在训练交互中从未出现，但我不声称它们在真实平台上刚刚发布。

另外，评论属于比较强的兴趣信号，但不是点击、播放时长或留存，因此离线结果只能说明评论偏好匹配能力，不能直接解释成 CTR 提升。”

### 1:15–2:05｜实验怎么保证可信

“我使用 MicroLens-50K，共有 359,708 条公开评论交互、50,000 名用户和 19,220 个视频。

实验按时间分成开发训练、Validation 和最终 Test。模型与规则只根据 Validation 选择，冻结以后才运行最终 Test。Test 中有 1,008 个训练阶段零交互的冷候选，对所有候选完整排序，没有抽样负例。

这样做的重点不是让数字更好看，而是避免反复查看 Test 后调参，导致结果不可信。”

### 2:05–2:50｜Text 和 Visual 有什么区别

“Text 是标题文本方案。它把用户过去评论视频的标题汇总成兴趣画像，再匹配新视频标题。例如历史标题里反复出现 anime、Naruto、battle，新标题也包含这些词，就会得到更高分。

Visual 是封面视觉方案。它比较用户历史视频和新视频的封面人物、物体、颜色和画面风格。

两者最终输出的都是新视频排序，只是利用的信息不同。”

此时切换到 Demo 的“方案对比”，展示“标题文本方案”和“封面视觉方案”。

### 2:50–3:35｜结果和方案取舍

“最终 Test 中，Text 的 Recall@10 是 0.12551，NDCG@10 是 0.07969；Visual 分别是 0.04543 和 0.02800。Text 在冻结核心指标上持续领先。

我也尝试了全局排名融合、低文本置信门控和学习式晚融合。但事前规则要求 Recall@10 和 NDCG@10 必须同时严格提升，三种融合都没有通过。

因此产品决策不是为了多模态标签强行上线，而是先保留低成本、可解释的 Text 方案。Visual 有一定信号，但目前不足以覆盖额外的特征提取、监控和回退成本。”

### 3:35–4:20｜Demo 能做什么

“Demo 有三个模式。

第一，实验样例展示真实 Validation 用户历史、离线正例和推荐结果。

第二，可以选择 1–6 条训练历史，按照正式实验同一画像公式创建模拟用户，并对全部 1,305 个 Validation 冷候选重新排序。每条结果还能看到主要相关历史。

第三，方案对比解释 Text、Visual 和融合方案的去留原因。

模拟用户没有后续真实行为，所以它只是新的推理，不是新的实验，也不计算准确率。”

### 4:20–5:00｜如果真正上线还缺什么

“这个项目完成的是推荐排序中的冷启动模块，不是抖音式完整产品。真正上线还需要真实上传时间、曝光和消费标签、信息流服务、反馈回流以及线上 A/B 实验。

我会先把 Text 作为新内容的低成本兜底策略，小流量验证有效消费或高意图互动，同时用跳失、不感兴趣、延迟和内容覆盖做护栏。零历史的新用户仍需热门、探索或其他独立策略处理。”

## 三、3 分钟压缩版结构

时间不足时只讲五段：

1. **问题**：新视频没有交互，传统 ID 推荐缺少信号。
2. **纠偏**：评论时间不是上传时间，因此只声称模型侧冷启动。
3. **实验**：时间切分，Validation 选方案，Test 只在冻结后运行一次。
4. **结论**：Text 明显优于 Visual，三类融合均未通过双指标门槛。
5. **产品决策**：先用 Text 做低成本兜底；线上价值仍需真实日志和 A/B 实验验证。

## 四、Demo 操作顺序

1. **实验样例**：选择一个 4 条以上历史的命中样例，指出“最近历史”“Validation 正例”和“Top-10”。
2. **创建模拟用户**：选择 2–3 条同主题历史，观察推荐；再增加一条其他主题历史，解释画像会发生变化。
3. **方案对比**：先讲 Text/Visual 区别，再看指标，最后讲三类融合为何被拒绝。

不要从指标表开场。先让面试官理解问题，再展示数字。

## 五、常见追问与简短回答

### 1. 这是根据点击历史推荐吗？

不是。当前数据是公开评论历史，代表相对高意图的正反馈，但不能等同于点击、观看或曝光。

### 2. 这是真实新发布视频冷启动吗？

不是严格的发布时刻冷启动。数据没有可靠上传时间，所以我只称它为模型侧 Item Cold-Start：候选视频在训练交互里从未出现。

### 3. 为什么简单 TF-IDF 反而是主方案？

因为当前目标是验证内容信号是否有效。TF-IDF 成本低、可解释，而且冻结指标明显优于当前视觉基线。复杂度本身不是价值。

### 4. Visual 更差是不是说明图片没有用？

不能这样说。当前 Visual 高于随机量级，也存在局部互补；但现有方法无法稳定判断何时应该依赖视觉，所以还不值得进入主链路。

### 5. 为什么不把 Text 和 Visual 直接相加？

已经测试过。全局融合的最优点退化为纯 Text；门控没有识别出视觉更可靠的人群；学习式融合只提升 NDCG、同时降低 Recall，均未通过事前门槛。

### 6. Demo 能直接给用户播放视频吗？

不能。它完成的是候选视频排序和解释，没有媒体文件、播放器、信息流服务和实时反馈闭环。

### 7. 新用户没有任何历史怎么办？

当前内容匹配方案需要用户历史。零历史用户要使用热门、探索、上下文或显式兴趣选择等独立策略，这不属于当前已验证范围。

### 8. 上线后看什么指标？

先由业务定义新内容的有效消费或高意图互动作为主指标，同时监控跳失、不感兴趣、投诉、延迟、覆盖和实验 SRM。不能直接沿用离线 Recall 作为业务收益。

### 9. 项目最大的限制是什么？

缺少真实上传时间、曝光和消费日志；评论用户也有选择偏差。因此项目能证明离线排序能力，不能证明线上因果价值。

### 10. AI 在项目里参与了什么？

应按真实情况回答。可以说明使用 AI 辅助代码实现、资料整理和文档校验，但不要声称自己独立完成不理解的技术细节。面试重点应放在你能够解释和负责的部分：问题定义、实验门槛、证据判断、产品取舍和风险边界。

## 七、禁止使用的表述

- “根据用户点击历史推荐”——当前是评论历史。
- “识别真实刚发布的视频”——没有可靠上传时间。
- “已经提升 CTR、播放时长或留存”——没有线上实验。
- “多模态融合最终上线”——三类融合都在 Validation 被拒绝。
- “这是一个类似抖音的完整推荐系统”——当前只是冷启动排序与解释模块。
- “这个项目完全由我独立编码”——如果使用了 AI 或其他协作工具，应如实说明。
