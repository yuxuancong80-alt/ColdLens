# 低文本置信度条件式模态门控

> 日期：2026-08-14  
> 范围：Validation Cold 用户内部分割；未运行最终测试模型指标

## 1. 为什么做门控

全局 Text–Visual rank fusion 没有超过 Text-only，但仍有 346 名用户在 Top-10 中仅被 Visual 命中。门控实验检验一个可证伪假设：当 Text 对完整冷候选池的最高 TF-IDF 余弦分数较低时，Visual 排名是否更可靠。

## 2. 预先冻结的规则

- 使用 `SHA-256("conditional-modality-gate-v1:<user_id>")` 首字节奇偶，将 13,750 名 Validation 用户稳定拆成 gate-dev 6,781 人和 gate-audit 6,969 人。
- 唯一置信度特征：每名用户对 1,305 个冷候选的最高 Text TF-IDF 余弦分数。
- 分数不高于阈值时整套切换到 Visual 排名，否则保留 Text 排名。
- 只在 gate-dev 检查视觉切换比例 `0%、10%、20%、30%、40%、50%`，阈值由 gate-dev 分数分位数产生。
- 以 NDCG@10 选择，Recall@10 为并列指标。
- 只有 gate-audit 的 NDCG@10 与 Recall@10 都严格超过 Text-only 才接受门控。

脚本先精确复现全体用户的既有 Text 与 Visual 端点，再执行门控。

## 3. gate-dev 结果

| 目标视觉比例 | 实际视觉比例 | Recall@10 | NDCG@10 | HitRate@10 |
|---:|---:|---:|---:|---:|
| 0% | 0.00% | **0.13985** | **0.09036** | **0.16826** |
| 10% | 10.01% | 0.13761 | 0.08896 | 0.16561 |
| 20% | 20.01% | 0.13657 | 0.08781 | 0.16443 |
| 30% | 30.01% | 0.13494 | 0.08615 | 0.16148 |
| 40% | 40.01% | 0.13007 | 0.08275 | 0.15573 |
| 50% | 50.01% | 0.12402 | 0.07880 | 0.14791 |

最佳比例是 0%，即不切换到视觉。最低 Text 最高分的10%包含679名用户，其中仅 Visual 命中17名、仅 Text 命中35名、两者都命中4名、两者都不命中623名。低最高分没有富集出 Visual 更可靠的人群。

## 4. gate-audit 与接受判定

因为 gate-dev 选择0%，传入 gate-audit 的冻结策略就是 Text-only：

- gate-audit Text / 冻结门控 Recall@10：0.11642；
- gate-audit Text / 冻结门控 NDCG@10：0.07407；
- 两者严格相等，不满足“两项都严格提升”的接受条件；
- 门控被拒绝，保留 Text-only。

这里不存在“非零门控在 audit 上失败”的结果：没有任何非零候选从 gate-dev 晋级。audit 的作用是执行冻结接受规则，不能被包装成额外提升证据。

## 5. 风险与解释边界

- gate-dev 与 gate-audit 的 Text Recall@10 分别为0.13985和0.11642，说明一次用户哈希拆分仍存在难度差异。有效比较是每个分组内部的配对变化，不能跨组直接比较绝对指标。
- 最高 Text 分数只衡量最强词汇匹配，不一定等价于置信度校准；它没有识别那批 Visual-only 命中用户。
- 继续尝试 margin、历史长度、多阈值树等规则会扩大验证集搜索空间。除非明确升级为一个新的、带独立验证设计的模型阶段，否则不应继续事后挖掘。
- 当前结论只针对冻结的 TF-IDF、MobileNetV3-Small、完整 Validation Cold 候选池和评论正反馈任务。

## 6. 当前决策

在现有轻量基线范围内：

- 拒绝全局 rank fusion；
- 拒绝低 Text 最高分条件门控；
- 保留 Text-only 作为当前最终候选；
- Visual-only、互补性 oracle 和两次失败融合保留为诚实的负结果。

若继续追求真正的多模态提升，应进入新的模型阶段，例如使用开发训练交互学习模态投影或用户条件权重，并为其单独定义容量、正则化和验证预算；不能继续在同一验证结果上无限追加启发式规则。
