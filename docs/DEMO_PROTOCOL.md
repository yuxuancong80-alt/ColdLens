# ColdLens 本地 Demo 协议 v1

> 冻结日期：2026-08-14  
> 目标：解释已有 Text-only 冷启动模型，不训练、不调参、不生成新 Test 指标

## 1. 数据边界

- 只读取 `dev_train`、`validation_cold`、Validation 冷候选和标题；
- 不读取 `final_train`、`test_cold`、最终 Test 报告或封面媒体；
- 不在浏览器中加载原始 CSV、ZIP、特征矩阵或真实用户 ID；
- Demo 数据由本地脚本生成到 `demo/public/demo-data.json`，该文件被 Git 忽略。

## 2. 用户样例选择

历史分层固定为：`1–3`、`4–6`、`7–10`、`11+`。

每个分层选择：

- 1 名 Text Top-10 至少命中一个 Validation 正例的用户；
- 1 名 Text Top-10 未命中任何 Validation 正例的用户。

同一分层和结果内，按 `SHA-256("coldlens_demo_v1:" + user_id)` 升序取第一名。共 8 个样例。该设计用于平衡展示成功与失败，**不代表真实命中率或人群占比**。

## 3. 展示字段

- 匿名编号，不导出原始 user ID；
- 训练历史总数及最近 6 条标题；
- Validation 正例标题，最多 4 条；
- Text Top-10、余弦分数、是否命中及贡献最大的 3 个匹配词；
- 模型和数据边界、Validation 总体指标、用户分层提示。

标题最长展示 180 个字符。截断仅影响展示，不影响排序。

## 4. 明确禁止

- 不把平衡样例解释成总体准确率；
- 不展示“AI 置信度百分比”，余弦相似度不是校准概率；
- 不根据 Demo 用户继续修改模型；
- 不声称推荐会提升 CTR、观看时长或留存；
- 不将公开评论标签描述为曝光或点击。

## 5. 模拟用户模式

模拟模式与实验样例完全分开：

- 默认模式允许用户从本地演示目录选择 1–6 条训练期历史视频；
- 每条历史视频先使用正式实验已冻结的 L2 归一化 TF-IDF 向量，选中向量求和后再次 L2 归一化，与正式模型 `build_user_profile` 的画像公式一致；
- 浏览器使用该画像对全部 1,305 个 Validation 冷候选重新排序，并为每条推荐显示余弦相似度最高的已选历史作为“主要相关历史”；
- 也可切换到预设兴趣或英文/数字兴趣词模式；
- 使用 Dev Train 冻结的 TF-IDF IDF，将输入文本转换为一个 L2 归一化临时兴趣向量；
- 在浏览器内与全部 1,305 个 Validation 冷候选标题向量做余弦相似度并取 Top-10；
- 展示被识别的词、未识别的词、匹配词和相似度；
- 不保存输入，不调用 API，不读取原始 CSV，不读取 Test。

历史演示目录按 6 个主题各固定抽取 60 条、共 360 条非空向量训练视频，并使用稳定哈希保证重复导出一致。它是为了让交互可操作而构造的主题平衡样本，不代表训练目录的类别占比、质量分布或推荐效果。目录不导出原始 item ID，只使用本地别名、截断标题和稀疏向量。

“主要相关历史”指候选与每条已选历史分别计算文本余弦相似度后分数最高的一条。它是局部匹配解释，不是因果归因，也不证明用户因为该历史而喜欢候选。

兴趣词模式的临时向量仍是“兴趣描述即画像”的交互近似，不等同于正式模型中“多个历史视频向量求和”的用户画像。候选向量、历史目录和标题只写入被 Git 忽略的本地 `demo-data.json`。

页面提供 6 类、共 58 个经过导出脚本核验的可识别英文兴趣词。词库用于降低输入门槛，不是模型的完整词表，也不表示数据只有这些兴趣；用户仍可输入冻结词表中的其他英文/数字词。

当前标题字段主要是英文翻译/转写，冻结 tokenizer 只识别小写英文字母和数字。中文兴趣输入会成为未识别词，不能声称具备中文语义理解。

模拟结果没有未来真实互动标签，因此：

- 不显示命中/未命中；
- 不计算 Recall、NDCG 或 HitRate；
- 不把结果加入原实验报告；
- 不根据模拟结果修改冻结模型。

## 6. 方案对比模式

方案对比模式只展示已经冻结并写入正式文档的汇总证据：

- 先用同一示例解释 Text 读取历史视频标题、Visual 读取历史视频封面，两者最终都输出新视频排序；
- Text-only 与 Visual-only 的 final Test Recall@10、NDCG@10 和 HitRate@10；
- 事前冻结的融合接受门槛：Recall@10 与 NDCG@10 必须同时严格优于 Text-only；
- 三类融合在 Validation 上被拒绝的原因；
- 当前优先采用 Text-only 的效果、工程成本、解释性与上线边界。

这些数字作为只读常量写入页面，并与 `docs/FINAL_TEST_RESULTS.md`、`docs/LEARNED_FUSION_RESULTS.md` 和 `docs/PORTFOLIO_CASE_STUDY.md` 对账。页面运行时不读取 Test 标签、`final_train`、最终报告文件或模型产物，也不产生新指标。三个融合方案没有 Test 数字，因为它们已在 Validation 被拒绝。

方案对比不得把“Text优于当前Visual基线”改写为“视觉永远无用”，也不得把离线差值换算成CTR、观看时长或留存收益。

## 7. 验收

- 导出脚本连续运行结果逐字节一致；
- 8 个匿名用户覆盖 4 个历史分层和命中/未命中两种状态；
- 页面在数据缺失时给出本地生成提示，而不是静默伪造样例；
- 前端构建不需要访问原始数据目录。
- 模拟模式覆盖完整 1,305 个冷候选，至少提供 6 个预设兴趣；
- 历史目录固定包含 360 条匿名训练视频，用户只能选择 1–6 条；
- 58 个页面兴趣词必须全部存在于冻结 IDF 与候选词表中；
- 已知历史组合的浏览器画像、Top-10 和主要相关历史必须与 Python 同口径参考结果一致；
- 已知兴趣词的浏览器排序必须与 Python 同口径参考排序一致；
- 零有效词时不产生伪推荐，并明确提示语言/词表限制。
- 方案对比中的冻结数字必须与正式报告一致，并明确区分 Test 汇总、Validation 决策和线上业务假设。
- 页面必须用“标题文本方案”和“封面视觉方案”解释英文名称，并明确当前交互推荐使用 Text。
